Turn one Claude Code session into a team that works in parallel across the subscriptions you already pay for.

Today

One Claude Code session. One subscription. One task at a time.

  • Sequential. Schema, then API, then UI. Nothing runs while you wait.
  • Open a second session to go faster and you become the copy-paste bus between them. Each one knows half.
  • Expensive. Opus does the hard design and the typo fix. Both count against the same limit.
  • The limit hits mid-task. Work stops until the window resets. The half-done branch and its reasoning sit in a chat.
  • Context does not survive. Compaction, a new session, tomorrow morning: you re-explain the plan.
  • Your Codex, Cursor and local models sit idle while Claude is capped.

With Atman

Your session plans and leads. Seats on every subscription do the work.

  • Parallel. Independent tasks run at the same time on different seats.
  • You put the expensive model where the hard decisions are. Cost tiers are on the board, so the choice is visible.
  • A limit reopens the ticket with its notes and branch, so another seat can pick it up.
  • Context lives on the board. Plan, decisions, handoffs and messages survive any session.
  • Codex, Cursor and local models join the same board as seats, each with its own identity, worktree and provider login.

Under the hood

A board of plain files 
.tickets/
  T-001.json      one file per ticket
  agents/         seats and harnesses
  messages.jsonl  append-only
  briefs/         skills per lane

Lives in your repo. Greppable, diffable, reviewable in a pull request. No server, no database, nothing leaves your machine except your agents talking to their own providers.

Tickets with a dependency graph

Ready is computed from the graph. A ticket opens the moment its prerequisites are accepted. Claims are atomic, so two seats never take the same one.

Message board 
cursor → sonnet   re T-003
  which endpoint refreshes the session?
sonnet → cursor   re T-003
  POST /auth/refresh, see T-002 notes

Tied to the ticket, kept forever, read by whoever holds it next. A seat wakes when a message is addressed to it.

Skills and briefs 
briefs/roles/docs.md
  login flow is now /auth/session
briefs/codex-mini.md
  run pytest before review; never push main

What one seat learns becomes standing context for every seat in that lane. Created from the chat, injected into every wake-up.

How a seat is spun up 
atm spawn codex-mini
  prompt   objective + role brief + seat brief
           + ticket body + handoff from deps + inbox
  cwd      its own git worktree
  identity TICKET_AGENT, TICKETS_DIR
  exec     codex -p "$(cat prompt)"   # or claude, cursor, your script

The CLI writes one prompt with everything the seat needs, starts the harness in its own worktree with its own identity and provider login, and wakes it again whenever there is work for it: a ready ticket, a held ticket, or a message addressed to it. No SDK, no protocol.

Review by a different seat 
T-001  submitted  opus    @ 4cfeaf5
T-001  accepted   sonnet  @ 4cfeaf5
T-002  ready      handed 4cfeaf5

Work comes back as a commit, never a summary. Another agent checks that exact commit before the next ticket opens. A "done" nobody checked stops the chain.

What that enables

Interchangeable seats 
— new session, next morning, any agent —
❯ continue the auth work
⏺ atm board · objective: Ship auth · T-002 in review · T-003 in flight (cursor)
⏺ atm next · T-006 docs · handoff: uuid keys, soft delete, POST /auth/refresh
Picking up where sonnet stopped. Nothing to re-explain.
  • Open a new session and it is current in one prompt. It reads the board, not your memory.
  • Swap the model. A reopened ticket goes to whichever seat you point at it, with its notes and branch.
  • Lose a seat, keep the work. A limit or a crash reopens the ticket. Nothing to retype.

A seat is a lane, not a persona. Same-provider recovery is tested; cross-provider is not yet verified end to end.

Persistent plans

The objective and the dependency graph live in your repo, not in a session. Compaction, a restart or tomorrow morning: the next session reads the plan instead of asking you for it.

Durable knowledge

Briefs per role and per seat. What one seat learns is injected into every later wake-up in that lane. Plain files you can read, edit and review, not a hidden memory.

Parallel by default

Every ready ticket can be claimed at the same time by a different seat. Claims are atomic, so two seats never do the same work.

Verified handoffs

Work comes back as a commit, never a summary. A different seat accepts that exact commit before the dependent ticket opens, and the successor's prompt carries the handoff.

Your model choice, visible

Model and cost tier sit on each seat. You put the expensive model where the hard decisions are. Turns and cost per ticket show when measured and stay blank when not.

Install

Clone it. Then point your Claude Code at your project.

git clone https://github.com/advitiyavashist/atman.git
cd atman && ./install.sh                  # Python 3.9 + Git. Links atm into ~/.local/bin

cd /path/to/your-project
atm quickstart --agent boss              # board, AGENTS.md and Cursor rules, so every agent sees it
  • Open Claude Code in the project and give it the objective. It plans on the board and spawns the seats.
  • Codex and Cursor pick up the same board from AGENTS.md. Local models join with one line.
  • macOS developer preview today. Open source, MIT.
